# プロジェクト設計ハブ（<プロジェクト名>）

<プロジェクト名> の設計規約への**振り分け表**。設計の中身はここに書かず、使うスキル・規約へのリンクだけを持つ（二重管理を避けるため）。
汎用スキル（`spec-driven-development` など）が設計フェーズで差し込み口として呼び出す。

## 差し込み口ごとの回答

| 場面 | このプロジェクトでの回答 |
|---|---|
| design の技術スタック欄 | TODO: 言語・フレームワーク・DB・テスト・実行環境・主要な制約（詳細な資料があればそのパス） |
| クラス・メソッド設計 | TODO: 使う設計スキル・手順（例: `contract-first-design`、`ddd-class-design`）、レイヤー配置・例外の規約のパス |
| テスト設計 | TODO: テスト規約・使うスキルのパス |
| API・認証・命名の規約 | TODO: エンドポイント命名、認証方式、エラー形式、バリデーションの規約のパス |
| DB スキーマ | TODO: スキーマ資料の場所と更新ルール（なければ行ごと削除） |
| ドメイン用語 | TODO: 用語集の場所と更新ルール（なければ行ごと削除） |
| 成果物の出力先 | TODO: 既定（`specs/YYYY-MM-DD_<feature-name>/`）以外を使うならパスを記入。既定のままなら「既定どおり」 |

## このハブを更新するとき

- 新しい設計スキルや規約を追加したら、該当する場面の行にリンクを足す
- 設計の中身（手順・チェックリスト）はここに書かず、各スキル・規約側に書く
