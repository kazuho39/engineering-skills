# scheduled task の雛形

案件ごとに scheduled task を1本作るときの定義。`{...}` の3か所（タスク名・プロファイルのパス・投稿先）だけ差し替える。
タスクの `cron` は朝夕2回（例: `30 8,17 * * *`）。

```markdown
---
name: daily-vuln-briefing-{案件名}
description: 毎日朝夕2回、{案件名} に関係する脆弱性（CISA KEV / 依存の audit）をまとめ、#{チャンネル名} に投稿
---

以下のスキルを読み込み、そこに書かれている手順で脆弱性ブリーフィング本文を作成してください。このファイルが作業指示の正本です。内容を書き換えたり自分の解釈で要約したりせず、書かれている手順・制約をそのまま実行すること。

{このスキルの絶対パス}/SKILL.md

プロファイル（引数）: {このスキルの絶対パス}/profiles/{案件名}.json

## 投稿（このタスクが定義する）
スキルの出力（ブリーフィング本文）を Slack の #{チャンネル名}（channel ID: {C...}）に、Slack MCP の `slack_send_message` で1通として投稿する。この投稿は、このタスクが明示的に求めている書き込み操作であり、実行してよい。

- 本文は Markdown のまま（`#` 見出しを含めて）投稿する。内容は変えない
- 本文が `該当なし` のときは投稿しない（ノイズ防止）
- 取得元がすべて失敗したときは、その旨だけの短いメッセージを投稿する（実行されたことが分かるように）
- 投稿に失敗しても状態は残らないので、再試行は不要。失敗した旨を報告する

## 実行上の注意
- サブエージェントに委譲せず、このセッション自身で全ステップを実行すること。
- 最後に、投稿したか／しなかったか（理由つき）を1行で報告すること。
```
