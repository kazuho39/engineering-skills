# Specification Template（要件定義テンプレート）

`specification` を作るときは、以下をベースに整理してください。

## 1. 背景

- いま何が課題か
- なぜこの変更が必要か

## 2. 目的

- この変更で達成したいこと
- 達成後に期待する状態

### 成功メトリクス

この機能が成功したと判断するための計測可能な指標：

| メトリクス | 現状値 | 目標値 | 計測方法 |
|-----------|-------|-------|---------|
| （例）注文完了率 | - | 80%以上 | Google Analytics |
| （例）エラー発生率 | - | 0.1%未満 | ログ監視 |

## 3. 対象ユーザー / 利用シナリオ

- 誰が使うか
- どの場面で使うか

## 4. スコープ

### スコープ内

- 今回対応する内容

### スコープ外

- 今回は対応しない内容

## 5. 機能要件

### ユーザーストーリー

| ID | As a... | I want to... | So that... | 優先度 |
|----|---------|-------------|-----------|-------|
| US-001 | （例）ログイン済みの一般顧客 | 注文フォームを送信したい | 商品を購入できる | Must |

### 必須要件

- （必須機能を列挙）

### 任意要件

- （あると良い機能を列挙）

### エッジケース

- （境界値・例外パターンを列挙）

## 6. 非機能要件

- 性能
- セキュリティ
- 可用性
- 保守性

## 7. 制約

- 技術制約
- 運用制約
- 互換性制約

## 8. リスク / 懸念点

- 想定リスク
- 未確定事項

## 9. 受け入れ条件

検証可能な条件を**Given-When-Then形式**で記載してください。

| ID | Given（前提） | When（操作） | Then（期待結果） |
|----|-------------|------------|----------------|
| AC-001 | （例）ログイン済みの一般顧客 | （例）注文フォームを送信する | （例）注文完了メッセージが表示される |
| AC-002 | （例）未ログイン状態 | （例）注文ページにアクセスする | （例）ログイン画面にリダイレクトされる |
| AC-003 | | | |
