# ADR Template（実装方針・意思決定の記録テンプレート）

`<親文書>-adr.md`（`design-adr.md` または `specification-adr.md`）を作るときのひな形。構成の考え方は [document-structure](document-structure.md) を参照。

- 方式の選択があり、代替案を比較したときだけ作る。
- 入口の文書（design.md / specification.md）の「実装方針の選定（ADR）」節には、「決定・主な理由」の表とこのファイルへのリンクだけを置く。

````markdown
# ADR（{design|specification}）: {機能名}

対象: [{design.md}](./{design.md}) の「実装方針の選定」。{もう一方の文書}側の意思決定は `{もう一方}-adr.md` に置く（あれば）。

## ADR-{N}: {決定のタイトル}

**推奨: {推奨する方針を1文で}**

| 観点 | 推奨案: {名前} | 代替案A: {名前} | 代替案B: {名前} |
|------|--------------|---------------|---------------|
| 実装コスト | {評価} | {評価} | {評価} |
| 複雑性 | {評価} | {評価} | {評価} |
| 保守性 | {評価} | {評価} | {評価} |
| 拡張性 | {評価} | {評価} | {評価} |
| リスク | {評価} | {評価} | {評価} |
| パフォーマンス | {評価} | {評価} | {評価} |
| {その他の観点} | {評価} | {評価} | {評価} |

**採用理由:**
- {理由}

**トレードオフ:**
- {デメリット・制約}。{受け入れる理由}

**採用しなかった案:**
- 代替案A: {理由}
- 代替案B: {理由}

**関連:** {他の文書・ACへの反映があれば書く}

（ADR ごとに繰り返す）

## 前提条件

- {前提1}（例: 特定のミドルウェアが利用可能、データ規模が想定内）

## 再検討トリガー（Decision Review Triggers）

以下の条件が変わった場合、再検討が必要：

- **{条件}**: {具体的な変化と、そのときに検討すること}
````
